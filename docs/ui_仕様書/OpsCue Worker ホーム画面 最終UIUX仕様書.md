## **3\. 今日やること**

本人が対応すべき、未完了のアクションを表示する。

表示対象は、既存のWorker業務仕様でアクションとして定義され、かつ本人が実行可能なものに限定する。

例えば勤務前日確認・当日確認などが該当する。単なる通知や閲覧済みのお知らせは含めない。

表示ルール

* 最大3件。期限超過、当日期限、期限が近い順に表示する。  
* 完了済み、取消済み、現在は操作できないものは表示しない。  
* 各項目には内容・対象勤務・期限・遷移先を表示する。  
* 4件以上ある場合は、残件数と確認先を表示する。  
* 0件の場合は「現在、対応が必要なことはありません」とコンパクトに表示する。

アクションの完了判定はサーバー側の業務状態を正とし、ホーム独自の完了フラグは作らない。

## **4\. 次の勤務**

今回の重要な決定として、進行中の勤務を未来の勤務より優先する。

### **表示優先順位**

1. 勤務中のシフト  
   勤務カードの見出しを「現在の勤務」に変更する。  
2. 本日これから開始するシフト  
   見出しは「次の勤務」。確認待ちなどの状態を表示する。  
3. 翌日以降の最も近いシフト  
   見出しは「次の勤務」。勤務日時の近い順に選ぶ。  
4. 対象シフトなし  
   「今後の勤務予定はありません」と表示する。

勤務中かどうかは、現在時刻だけで断定せず、既存の勤怠状態や勤務状態と整合する判定を使用する。打刻漏れなどで状態が不明な場合は、誤って「勤務中」と表示しない。

勤務カードには、勤務日、時間、案件・業務、勤務先、確認状態を表示する。勤務先情報はシフトに保持されたスナップショットを参照する。

カードを押すと勤務詳細に遷移する。ホームから直接配置変更や勤怠確定は行わない。

## **5\. 募集中の仕事**

本人が実際に応募可能な募集のみを表示する。

公開中であっても、応募締切済み、取消済み、応募済みで再応募できないもの、既存の応募資格条件を満たさないものは対象外とする。

勤務可否が`UNKNOWN`または`要相談`の場合の扱いは、未解決のP0-4と整合させる必要があるため、このUI仕様だけで応募可否を確定しない。

| 項目 | 仕様 |
| ----- | ----- |
| 件数 | 最大2件 |
| 並び順 | 勤務開始日が近い順 |
| 表示 | 日付・業務名・時間・勤務先 |
| 状態 | 応募受付中 |
| 操作 | 募集詳細へ遷移 |
| 一覧 | 「すべて見る」から募集タブへ |
| 0件 | 現在応募できる仕事はありません |

ホームのカードは応募可能性をサーバー側で判定した結果から表示する。カード表示後に締切や定員が変わる可能性があるため、最終的な応募可否は応募実行時に再検証する。

## **6\. 挨拶・名前の表示**

正式表示は「こんにちは、〇〇さん」。

表示名はスタッフプロフィールから取得し、氏名が取得できない場合は「こんにちは」と表示する。

時間帯で挨拶を切り替える機能は初期実装では不要。名前が長い場合は折り返しまたは省略表示し、レイアウトを崩さない。

## **8\. 権限・セキュリティ**

Workerホームは、認証された本人に許可された情報のみ取得する。

本人以外の応募、配置、勤怠、アクションを表示しない。支店や募集条件によるアクセス制御もサーバー側で行う。

UIで項目を隠すだけでは権限制御とみなさず、既存のRLS・RPC・認可ロジックと照合する。

取得エラーとデータ0件を区別し、認証期限切れの場合は既存の再認証フローへ誘導する。

## **9\. 実装順序**

| 段階 | 作業 | 優先度 |
| ----- | ----- | ----- |
| 1 | 既存ホーム・取得API・RLSの棚卸し | P0 |
| 2 | 今日やることの取得条件・並び順 | P0 |
| 3 | 勤務中優先の勤務カード | P0 |
| 4 | 応募可能な募集の抽出 | P0 |
| 5 | 名前付き挨拶・空状態・エラー表示 | P0 |
| 6 | モバイル・PCのレイアウト調整 | P0 |
| 7 | 遷移・アクセシビリティ・E2E検証 | P1 |

PR-02・PR-03のDraft状態を維持し、これらのマージやDB変更をWorkerホームのUI作業に便乗させない。

## **10\. 完了判定**

次の条件を満たせば、WorkerホームのUI実装を完了と判断できる。

* 本人のアクションだけが最大3件表示される。  
* 勤務中のシフトが未来のシフトより優先される。  
* 勤務先情報はシフトのスナップショットと一致する。  
* 本人が応募可能な仕事だけが最大2件表示される。  
* 各カードから正しい詳細画面へ遷移できる。  
* データ0件、取得エラー、読み込み中が適切に区別される。  
* スマホとPCで操作でき、既存のナビゲーションが維持される。  
* 認可されていないデータが取得・表示されない。
