# **OpsCue Worker「マイページ」最終UI/UX仕様書**

## **1\. 最終決定事項**

| 項目 | 確定仕様 |
| ----- | ----- |
| 電話番号 | Workerが変更申請、Adminが確認・承認 |
| 氏名・所属 | Workerは閲覧のみ、変更はAdminへ問い合わせ |
| メールアドレス | 認証基盤の本人確認付き変更手続き |
| スキル | Workerが申請、Adminが承認 |
| 資格 | Workerが申請、Adminが承認 |
| 勤務可能時間 | 独立画面で管理 |
| 希望条件 | 独立画面で管理 |
| OpsCue内通知 | 常時有効、WorkerはOFFにできない |
| LINE通知 | カテゴリ別ON/OFFを変更可能 |
| LINE連携 | 独立画面で管理 |
| パスワード | 認証方式に応じて変更 |
| ログアウト | 確認後にセッション終了 |

設計原則は、本人が申請できることと、正式な登録情報を変更できることを分離すること。

プロフィールカードを選択すると基本情報へ遷移する。

# **4\. 基本情報**

## **4.1 表示項目と編集権限**

| 項目 | Worker操作 | 更新方法 |
| ----- | ----- | ----- |
| スタッフID | 閲覧のみ | システム管理 |
| 氏名 | 閲覧のみ | Adminへ変更依頼 |
| フリガナ | 閲覧のみ | Adminへ変更依頼 |
| メールアドレス | 閲覧・変更手続き | 認証基盤で確認 |
| 電話番号 | 閲覧・変更申請 | Admin承認後に反映 |
| 所属拠点 | 閲覧のみ | Admin管理 |
| アカウント状態 | 閲覧のみ | Admin管理 |
| 登録日時 | 閲覧のみ | システム管理 |

電話番号はWorkerが直接UPDATEできない。

変更申請が承認されるまでは、既存の電話番号を正式な登録情報として保持する。

## **4.2 電話番号変更申請**

## **電話番号の変更申請**

現在の電話番号

090-1234-5678

新しい電話番号  
変更理由（任意）

申請後の反映について

管理者が内容を確認し、承認された場合に登録情報へ反映されます。

変更を申請するフォームのUI例。実際の申請は送信されません。

### **入力項目**

| 項目 | 必須 | 仕様 |
| ----- | ----- | ----- |
| 現在の電話番号 | 自動表示 | 編集不可 |
| 新しい電話番号 | 必須 | 形式検証 |
| 変更理由 | 任意 | 最大500文字 |
| 申請確認 | 必須 | 変更前後を表示 |

電話番号は表示時のハイフン有無と保存時の正規化ルールを統一する。

新しい電話番号が現在の番号と同じ場合は申請不可。

同じWorkerの電話番号変更申請が審査中の場合は、重複申請を防ぐ。

### **申請状態**

| 状態 | Worker表示 | 操作 |
| ----- | ----- | ----- |
| 申請中 | 管理者確認中 | 内容確認 |
| 承認 | 変更完了 | 最新番号を確認 |
| 差戻し | 修正が必要 | 修正して再申請 |
| 却下 | 変更は承認されませんでした | 理由確認 |
| 取下げ | 申請を取り下げました | 履歴確認 |

申請中の電話番号は正式な連絡先として使用しない。

Adminが承認した時点で正式な電話番号を更新し、申請を承認済みにする。

承認処理と正式情報の更新は、整合性が保たれる一つのサーバー側処理として実行する。

# **5\. スキル・資格**

## **5.1 基本方針**

スキルも資格もAdmin承認が必要。

Workerの自己申告だけでは、配置条件や応募資格を満たす正式な情報として扱わない。

### **画面構成**

スキル・資格  
├─ 登録済み一覧  
│  ├─ 確認済み  
│  ├─ 有効期限切れ  
│  └─ 更新申請中  
│  
├─ 申請履歴  
│  ├─ 申請中  
│  ├─ 承認  
│  ├─ 差戻し  
│  ├─ 却下  
│  └─ 取下げ  
│  
└─ 追加・更新申請

## **5.2 登録済み一覧**

| 項目 | 内容 |
| ----- | ----- |
| スキル・資格名 | マスタから取得 |
| 区分 | スキル・資格 |
| 確認状態 | 確認済み等 |
| 有効期限 | 対象資格のみ |
| 更新申請状況 | 申請中の場合 |
| 操作 | 詳細・更新申請 |

未承認の新規申請は、正式な登録済み一覧へ混ぜず、申請履歴に表示する。

承認済みのスキル・資格に更新申請がある場合は、現在の正式情報を保持したまま「更新申請中」を表示する。

## **5.3 追加・更新申請**

| 項目 | 必須 | 仕様 |
| ----- | ----- | ----- |
| 申請区分 | 必須 | 追加・更新 |
| スキル・資格 | 必須 | マスタから選択 |
| 取得日 | 条件付き | マスタ定義に従う |
| 有効期限 | 条件付き | 対象資格のみ |
| 補足説明 | 任意 | Adminへの説明 |
| 証明書 | 条件付き | 必要な場合のみ |
| 申請確認 | 必須 | 内容確認後に送信 |

証明書が必要な場合は、非公開ストレージとアクセス制御を使用する。

ファイル形式、容量、保存期間は実装前に既存契約を確認して確定する。

### **申請状態**

| 状態 | Worker操作 | 正式登録への影響 |
| ----- | ----- | ----- |
| 申請中 | 内容確認 | なし |
| 承認 | 結果確認 | 反映 |
| 差戻し | 修正・再申請 | なし |
| 却下 | 理由確認 | なし |
| 取下げ | 履歴確認 | なし |

申請承認はAdminのみ実行可能。

承認時には、申請内容とマスタの最新状態を再検証する。

期限切れ資格、未承認スキル、申請中の資格を、応募資格・配置条件を満たすものとして扱わない。

# **6\. 勤務可能時間**

勤務可能時間は、特定の日付・時間帯の勤務可否を管理する独立画面。

既存の「勤務可能・相談可能・勤務不可」の3状態を維持する。

| 項目 | 内容 |
| ----- | ----- |
| 対象日 | 日付選択 |
| 開始日時 | 開始時刻 |
| 終了日時 | 終了時刻 |
| 可否 | 勤務可能・相談可能・勤務不可 |
| 登録一覧 | 期間別表示 |
| 操作 | 追加・編集・削除 |

### **業務ルール**

| 状態 | 意味 |
| ----- | ----- |
| 勤務可能 | 登録範囲で勤務可能 |
| 相談可能 | 条件次第で勤務可能 |
| 勤務不可 | 登録範囲で勤務不可 |
| UNKNOWN | 登録なし・判断不能 |

UNKNOWNを勤務可能とみなさない。

相談可能を自動的に勤務可能へ変換しない。

勤務可能時間の変更で確定済みAssignmentを自動取消しない。

勤務予定と矛盾する変更がある場合は警告を表示する。

# **7\. 希望条件**

希望条件は、普段の働き方に関する希望を登録する独立画面。

勤務可能時間のように、特定日時の勤務可否を確定するものではない。

### **表示・編集項目**

| 項目 | 内容 |
| ----- | ----- |
| 希望曜日 | 月〜日 |
| 希望開始時刻 | 時刻 |
| 希望終了時刻 | 時刻 |
| 翌日終了 | チェック |
| 希望エリア | 選択 |
| 希望業務 | 選択 |
| 交通手段 | 選択 |
| 最終更新日時 | 表示 |

以前のスクリーンショットにあった項目構成を維持する。

希望条件が未登録の場合は「未設定」と表示する。

希望条件に一致しないことだけを理由に、応募や配置を自動禁止しない。

## **8.1 最終方針**

Workerが変更できるのはLINE通知のカテゴリ別ON/OFFのみ。

OpsCue内通知は常時有効とし、Workerによる無効化を認めない。

### **画面イメージ**

LINE連携済みを想定した設定例。変更内容は保存されません。

### **通知カテゴリ**

| カテゴリ | OpsCue内通知 | LINE |
| ----- | ----- | ----- |
| 応募結果 | 常時有効 | ON/OFF |
| 勤務確定・変更 | 常時有効 | ON/OFF |
| 前日確認 | 常時有効 | ON/OFF |

# **9\. LINE連携**

LINE連携は通知設定と独立した画面にする。

### **表示項目**

| 項目 | 内容 |
| ----- | ----- |
| 連携状態 | 未連携・連携済み・再連携が必要 |
| 連携日時 | 連携済みの場合 |
| リマインダー設定 | LINE通知設定へのリンク |
| 操作 | 連携・再連携・解除 |

### **状態と操作**

| 状態 | 表示 | 操作 |
| ----- | ----- | ----- |
| 未連携 | LINE未連携 | 連携する |
| 連携済み | LINE連携済み | 設定・解除 |
| 再連携が必要 | 接続を確認してください | 再連携 |
| 処理中 | 連携処理中 | 重複操作不可 |
| 失敗 | 連携に失敗しました | 再試行 |

LINE連携を解除してもOpsCue内通知、勤務情報、問い合わせ履歴は削除しない。

LINEから正式な勤務操作を実行しない。

連携・解除処理では、本人確認と連携先の一致を検証する。

# **10\. アカウント管理**

### **パスワード変更**

認証方式に応じて提供する。

メール・パスワード認証の場合は、既存の認証基盤の変更手続きを使用する。

外部認証のみのWorkerに、利用できないパスワード変更フォームを表示しない。

### **ログアウト**

ログアウト時は確認ダイアログを表示する。

ログアウト成功後はログイン画面へ遷移する。

未保存の入力がある場合は、ログアウト前に警告を表示する。

### **サーバー側の必須条件**

WorkerはAPIリクエストを改変しても、氏名・所属・ロール・正式電話番号・承認済みスキル資格を直接更新できない。

申請データと正式データを分離する。

Adminの承認処理では、対象Worker、申請状態、承認権限、現在の正式データを再検証する。

Adminの権限は既存の拠点・担当範囲に従う。

# **15\. エラー・競合状態**

| ケース | 処理 |
| ----- | ----- |
| プロフィール取得失敗 | 再試行 |
| 電話番号形式不正 | 入力エラー |
| 同じ番号への変更 | 申請不可 |
| 電話番号変更申請が審査中 | 重複申請防止 |
| 申請中にAdminが電話番号を変更 | 競合検出・再確認 |
| スキル・資格マスタが無効 | 申請不可 |
| 同じ資格の申請が審査中 | 重複申請防止 |
| 資格が期限切れ | 正式な有効資格として扱わない |
| 勤務可能時間の重複 | 既存契約に従い検証 |
| 勤務可能時間と確定勤務が矛盾 | 警告 |
| LINE設定保存失敗 | 設定を再取得 |
| LINE連携失敗 | 再試行 |
| LINE解除失敗 | 既存状態を保持 |
| 認証セッション切れ | 再ログイン |
| 二重送信 | 冪等処理 |
| 権限不足 | 操作拒否・情報非公開 |

申請承認と正式データの更新は一貫した処理として実行し、途中失敗で「承認済みなのに正式データが更新されていない」状態を作らない。
