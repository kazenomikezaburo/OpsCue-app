# **OpsCue Admin シフト運用 詳細UI/UX仕様書 v1.0**

## **1\. 全体の画面構成**

シフト運用は、次の6つの主要画面群で構成する。

| 画面 | 目的 | 表示形式 |
| ----- | ----- | ----- |
| シフト一覧 | 全案件のシフトを横断管理 | 独立ページ |
| シフト作成 | 単日・複数日のシフトを登録 | 独立ページ |
| シフト詳細 | 1シフトの情報・応募・配置・確認 | 独立ページ |
| シフト編集 | 勤務条件・募集条件を変更 | 独立ページ |
| 配置・休憩回し | スタッフの担当と休憩を時間軸で編集 | 専用ワークスペース |
| 前日・当日確認 | 複数シフトの回答状況を横断確認 | 独立ページ内タブ |

サイドバーの「シフト運用」は、引き続き1つのナビゲーション項目にする。内部で一覧・前日確認・当日確認を切り替える。

### **入力ルール**

案件を選ぶと、その案件に属する有効な業務だけを候補として表示する。業務を選択すると勤務先情報を読み取り専用で表示する。

日付の複数選択では、重複日付の排除、日付ごとの勤務時間の上書き、作成予定件数の表示を行う。

作成前プレビューでは、対象シフトの一覧を表示し、重複・期間外・時刻不整合などのエラーを確認する。

保存はプレビュー後の最終確定ボタンで行い、二重送信を防止する。

## **5\. シフト編集画面**

作成と同じ入力コンポーネントを使うが、対象は1件のみ。

| セクション | 内容 |
| ----- | ----- |
| 基本情報 | 案件・業務・勤務先（原則読み取り専用） |
| 勤務条件 | 日時・休憩条件・必要人数 |
| 募集条件 | 締切・状態・備考 |
| 影響確認 | 応募・配置・確認回答への影響 |
| 保存 | キャンセル・変更保存 |

日時や必要人数などを変更するときは、関連する応募・配置・確認回答への影響を確認する。

特に配置済みスタッフがいる場合は、単純なフォーム保存だけで既存配置が消えないようにする。

## **7-2. 画面を5つの領域に分ける**

| 領域 | 内容 |
| ----- | ----- |
| A. ヘッダー | シフト情報・保存状態・戻る |
| B. 集計 | 配置人数・未配置・不足時間帯・警告 |
| C. ツールバー | スタッフ追加・ポジション追加・時間刻み・印刷 |
| D. タイムライン | スタッフ × 時間 × 担当・休憩 |
| E. 固定フッター | 変更破棄・下書き保存・確定 |

タイムラインでは、スタッフ名の列と時刻の行を固定し、横スクロールしても誰の時間割か分かるようにする。

## **7-3. タイムラインの操作**

編集モードの選択例

時間の刻み  
5分15分30分  
追加するブロック  
担当業務  
休憩

15分刻みで担当業務ブロックを追加する設定。

操作は次のようにする。

* 空白部分をドラッグして担当・休憩を追加。  
* ブロックを横方向にドラッグして時間を移動。  
* ブロックの左右端をドラッグして時間を伸縮。  
* ブロックを選択すると右ドロワーで時刻・担当を正確に入力。  
* キーボード操作でも追加・編集・削除できるようにする。  
* Undo / Redoに対応する。

スタッフの勤務時間外への配置や、休憩との重複は警告または保存禁止とする。禁止すべき条件は既存の業務ルールと整合させる。

## **7-4. 右ドロワーの種類**

専用ワークスペースで使うドロワーは3種類に統一する。

| ドロワー | 入力・操作 |
| ----- | ----- |
| スタッフ選択 | 氏名・資格・勤務可能時間・配置状況 |
| 担当編集 | スタッフ・ポジション・開始・終了時刻 |
| 休憩編集 | スタッフ・開始・終了時刻・休憩種別 |

同時に複数のドロワーを開かず、常に1つだけ表示する。

スタッフ選択では、候補者の検索・絞り込み・選択を行う。すでに他シフトへ配置されているスタッフや、資格不足のスタッフは明確に区別する。

## **7-5. Coverage（充足状況）**

タイムラインの下に、時間帯別の必要人数・実際の配置人数・不足人数を表示する。

時間帯別の充足状況

| 時間 | 必要 | 配置 | 不足 |
| :---- | :---- | :---- | :---- |
| 09〜10 | 4 | 4 | 0 |
| 10〜11 | 5 | 4 | 1 |
| 11〜12 | 5 | 3 | 2 |
| 12〜13 | 4 | 4 | 0 |

例示用データ。休憩中のスタッフは配置人数に含めない。

重要なのは、単に8人配置されているから充足とするのではなく、時間帯ごと・ポジションごとに必要人数を満たしているか確認すること。

休憩を追加すると、その時間帯の充足状況が再計算される。

## **8\. 前日確認・当日確認**

既存の横断確認画面は維持し、詳細ドロワーの共通部分を統一する。

| 項目 | 前日確認 | 当日確認 |
| ----- | ----- | ----- |
| 主目的 | 翌日の勤務可否確認 | 当日の勤務状況確認 |
| 優先表示 | 未回答・勤務不可・要対応 | 未確認・遅延・要対応 |
| 一覧単位 | シフト・スタッフ | シフト・スタッフ |
| 詳細 | 回答・連絡・対応履歴 | 確認・勤務状況・対応履歴 |
| 操作 | 確認・連絡・対応記録 | 確認・連絡・対応記録 |

シフト詳細の確認タブは、そのシフトだけを表示する。横断確認画面では全案件の対象シフトをまとめて扱う。

前日・当日確認の状態と、勤怠の実績状態は区別する。

## **9\. レスポンシブ設計**

| UI | PC | タブレット | スマホ |
| ----- | ----- | ----- | ----- |
| シフト一覧 | テーブル | 簡略テーブル | カード |
| シフト詳細 | 2カラム | 1〜2カラム | 1カラム |
| シフト作成 | 2カラム入力 | 1〜2カラム | 1カラム |
| 応募・確認ドロワー | 右固定 | 右固定 | 全画面 |
| 配置タイムライン | 全幅編集 | 横スクロール | 横スクロール＋リスト編集 |
| 保存フッター | 右寄せ | 右寄せ | 下部全幅 |

スマホでタイムラインのドラッグ操作を無理に再現する必要はない。

スマホではスタッフを選び、担当・休憩を時間入力フォームから編集できるようにする。タイムラインは確認用として横スクロールできれば十分。

## **11\. 実装優先順位**

10月31日の技育展デモを考慮して、段階的に実装する。

| 優先度 | 機能 | デモで必要な範囲 |
| ----- | ----- | ----- |
| P0 | シフト一覧 | 一覧・検索・詳細遷移 |
| P0 | シフト作成 | 案件・業務選択、日程、人数、作成確認 |
| P0 | シフト詳細 | 概要・応募・配置・確認の4タブ |
| P0 | シフト編集 | 基本条件の編集 |
| P0 | 配置・休憩回し | タイムライン表示・担当・休憩の編集 |
| P1 | 週・月表示 | シフト・不足状況の可視化 |
| P1 | 前日・当日確認 | 横断一覧・詳細 |
| P1 | Coverage | 時間帯別の不足表示 |
| P2 | Undo / Redo | 操作履歴 |
| P2 | 印刷・PDF | 紙の休憩回し表の出力 |
| P2 | 休憩の自動分散 | 自動配置補助 |

ここでのP0は、まずモックデータを使って画面遷移と操作が成立することを目標にする。バックエンド接続は別工程とし、既存の認可・配置RPCの修正が終わっていない段階で実データの変更を無理に接続しない。

## **12\. 最終的に確定するUI方針**

今回のB案により、シフト運用の基本設計は次のように固定する。

* 一覧：全案件のシフトを探す・状況を把握する。  
* 作成・編集：独立ページで勤務条件を登録する。  
* 詳細：概要・応募・配置・確認を4タブで管理する。  
* 配置・休憩回し：紙の表に近い、スタッフ×時間の専用ワークスペース。  
* 右ドロワー：スタッフ選択、担当ブロック、休憩ブロックの個別編集。  
* 前日・当日確認：横断画面を維持し、シフト詳細と情報を共有する。
