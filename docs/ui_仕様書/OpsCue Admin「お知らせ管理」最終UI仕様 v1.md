## **5\. 公開対象の固定ルール**

ここは今回の重要な決定事項。

公開時点で対象となるWorkerのIDを確定し、公開後に対象者を自動増減させない。

例えば、10月22日に名古屋支店の有効Workerが25人いた場合、公開対象はその25人に固定される。

公開対象の固定イメージ

25人

公開時点

25人に固定

公開後

後から入社・登録されたWorkerには自動公開しない。退職・停止したWorkerへのアクセスは、アカウント権限を優先して制御する。

### **対象者の確定手順**

1. 管理者が公開対象支店を選択する。  
2. 「公開する」を押すと、サーバー側で対象Workerを再計算する。  
3. 公開確認ダイアログに支店・対象人数・重要度を表示する。  
4. 管理者が確定すると、対象者IDのスナップショットとお知らせ公開状態を保存する。  
5. 対象者に通知を配信する。

公開確認後に対象者が変わる競合を避けるため、公開確定時のトランザクションで対象者を決定する。

公開済みのお知らせを編集しても、対象者のスナップショットは変更しない。

公開対象支店の変更は公開後には許可しない。 別の支店へ周知したい場合は新しいお知らせを作成する。

## **6\. 公開後の編集と変更履歴**

公開後の編集を許可するが、変更前の内容を必ず残す。

### **編集可能な項目**

| 項目 | 下書き | 公開中 |
| ----- | ----- | ----- |
| タイトル | 編集可 | 編集可 |
| 本文 | 編集可 | 編集可 |
| 重要度 | 編集可 | 編集可 |
| 公開対象支店 | 編集可 | 変更不可 |
| 公開対象者 | 未確定 | 変更不可 |
| 公開日時 | 未設定 | 変更不可 |
| 状態 | 公開操作 | アーカイブ操作 |

公開中の編集保存時は、変更内容の確認ダイアログを表示する。

変更履歴には、変更前後のタイトル・本文・重要度、変更者、変更日時、バージョン番号を保持する。

履歴は管理者専用とし、Worker側には最新版だけを表示する。Workerには最終更新日時と「更新済み」を表示する。

### **変更履歴ドロワー**

右ドロワー幅は480〜560px程度。

上部に「v2・更新日時・更新者」、本文に変更項目を表示する。

本文変更については、変更前・変更後を比較できるようにする。長文の場合はスクロール可能にする。

編集履歴は削除不可とする。

## **7\. 状態遷移**

下書き  
公開中  
アーカイブ

初期実装ではアーカイブからの再公開は行わない。

| 現在 | 操作 | 次の状態 |
| ----- | ----- | ----- |
| 新規 | 下書き保存 | 下書き |
| 下書き | 編集保存 | 下書き |
| 下書き | 公開 | 公開中 |
| 下書き | 削除 | 削除済み |
| 公開中 | 編集保存 | 公開中 |
| 公開中 | アーカイブ | アーカイブ |
| アーカイブ | 詳細確認 | アーカイブ |

公開中のお知らせは物理削除できない。アーカイブ後も監査目的のデータと履歴を保持する。

下書き削除は確認ダイアログを必須とし、既存の監査・保持ポリシーに従う。

### **アーカイブ時のWorker表示**

アーカイブされたお知らせは、Workerの通常のお知らせ一覧・詳細から非表示にする。通知からアクセスしても公開終了を表示する。

過去の通知や監査履歴は保持する。

## **8\. 操作権限**

| 操作 | Manager | System Admin | Worker |
| ----- | ----- | ----- | ----- |
| 一覧閲覧 | 管理対象支店 | 権限範囲内 | 対象のお知らせのみ |
| 下書き作成 | 許可 | 許可 | 不可 |
| 下書き編集 | 権限範囲内 | 権限範囲内 | 不可 |
| 公開 | 公開権限がある場合 | 公開権限がある場合 | 不可 |
| 公開後編集 | 編集権限がある場合 | 編集権限がある場合 | 不可 |
| アーカイブ | 管理権限がある場合 | 管理権限がある場合 | 不可 |
| 変更履歴閲覧 | 権限範囲内 | 権限範囲内 | 不可 |
| お知らせ閲覧 | 管理権限内 | 管理権限内 | 固定された対象者のみ |

System Adminでも、認可された範囲を超えて操作できるとは仮定しない。

Workerは公開対象スナップショットに含まれ、かつ現在もアカウント利用権限が有効な場合だけ閲覧可能とする。

支店を移動した場合も、公開時点の対象者であった事実は維持する。ただし、アカウント停止・権限失効などは優先する。

## **9\. 通知仕様**

### **通知を発生させるイベント**

| イベント | 通知先 | 動作 |
| ----- | ----- | ----- |
| 初回公開 | 固定された対象Worker | 新着お知らせ通知 |
| 重要なお知らせ公開 | 固定された対象Worker | 重要表示付き通知 |
| 公開後編集 | 固定された対象Worker | 更新通知 |
| アーカイブ | 原則通知なし | Worker側から非表示 |
| 下書き保存 | 通知なし | 管理者のみ |

公開後の編集では、タイトル・本文・重要度に実質的な変更があった場合に更新通知を送る。空白の正規化などで実質変更がない場合は新しい履歴や通知を作らない。

通知の重複送信を防ぐため、公開イベント・編集バージョンと対象Workerをキーに冪等性を確保する。

通知を押すとWorkerのお知らせ詳細に遷移する。

### **既読管理について**

初期実装では次の機能を導入しない。

* 既読・未読人数  
* 既読率  
* スタッフごとの閲覧履歴  
* 未読者への再通知

ただし将来追加しやすいように、お知らせID・公開バージョン・対象Worker IDを安定して管理する。

## **10\. エラー・空状態**

| 状況 | 表示・動作 |
| ----- | ----- |
| お知らせ0件 | 新規作成を案内 |
| 検索結果0件 | 条件を変更する案内 |
| 下書き保存失敗 | 入力内容を保持して再試行 |
| 公開対象0人 | 公開を停止し対象を見直す |
| 公開権限なし | 公開操作を無効化 |
| 公開中の同時編集 | 競合を検出し再確認 |
| 公開失敗 | 公開状態を再取得して結果を確認 |
| 通知配信失敗 | 公開状態は維持し通知を再試行 |
| アーカイブ済み | 編集・公開操作を表示しない |
| Workerの対象外アクセス | アクセス不可 |
| 取得エラー | 空状態と区別して再試行 |

公開処理は、お知らせ本体と対象者スナップショットを一貫して保存する。途中失敗で「公開中なのに対象者がいない」といった不整合を作らない。

## **12\. 実装順序**

Phase 1

既存仕様・安全性の調査

P0

既存のお知らせテーブル、RPC、RLS、通知、支店権限、Worker表示を読み取りで確認。

Phase 2

公開対象スナップショット

P0

公開時点の対象Worker確定、保存、認可を実装。公開処理の原子性と冪等性を検証。

Phase 3

一覧・詳細ページ

P0

既存一覧を改善し、詳細・状態表示・検索・空状態を追加。

Phase 4

作成・下書き・公開

P0

既存フォームを活かし、バリデーション・公開確認・状態遷移を整備。

Phase 5

公開後編集・履歴

P0

編集画面、バージョン管理、競合検出、履歴ドロワー。

Phase 6

アーカイブ・Worker表示

P1

公開終了、Worker側の閲覧制御、通知からのアクセス時の表示。

Phase 7

通知連携

P1

初回公開・更新通知、重複防止、再試行。

Phase 8

統合テスト

P1

支店分離、対象者固定、同時編集、権限、スマホ表示、エラー処理を検証。

既存のDB変更や進行中のPRとは独立して実装する。安全な公開・編集RPCが存在しない場合、フロントエンドから直接テーブル更新する形で代用しない。

## **13\. 完了条件**

* 一覧で状態・重要度・公開対象を確認できる。  
* 下書きを途中保存できる。  
* 公開前に内容と対象人数を確認できる。  
* 公開対象者が公開時点で固定される。  
* 公開後にタイトル・本文・重要度を編集できる。  
* 編集履歴がすべて保持される。  
* 公開対象を公開後に変更できない。  
* アーカイブ後はWorkerから閲覧できない。  
* 初回公開・更新時に通知できる。  
* 通知の重複・失敗を適切に処理できる。  
* Manager・System Admin・Workerの権限が守られる。  
* PCとスマホで問題なく操作できる。  
* 既読管理がなくても運用できる。
