# **OpsCue Admin「取引先・勤務先マスタ管理」最終UI仕様**

| 項目 | 確定仕様 |
| ----- | ----- |
| 詳細画面 | 独立ページを作らない |
| 一覧 | 独立ページ、PCテーブル・スマホカード |
| 追加・編集 | 右ドロワー |
| 無効化 | 関連データへの影響を警告したうえで実行可能 |
| 削除 | 原則として物理削除しない |
| 勤務先情報 | マスタ＋シフト側スナップショット |
| 過去の勤務記録 | 当時の情報を保持 |
| 将来の勤務案内 | 明示的な反映操作で更新 |
| 変更履歴 | 変更者・日時・変更前後の値を記録 |
| 権限制御 | Manager / System Adminの許可範囲に従う |

ここで確定するのはプロダクト仕様。現在のDB・RPC・RLSがこの設計に対応しているかは未検証なので、実装前の棚卸しを必須とする。

## **1\. データの関係**

既存のOpsCueの情報構造は変更しない。

取引先マスタ

取引先は案件に紐づき、勤務先は業務に紐づく。シフトは業務の勤務先を継承し、必要な案内情報をスナップショットとして保持する。

勤務先と取引先を直接の親子関係にはしない。同じ会場を複数の取引先が利用できるため。

## **5\. 勤務先マスタ＋シフトスナップショット**

C案採用

この方式を正式採用する。

### **5.1 保存する情報**

勤務先マスタは最新の基本情報を保持する。

シフト側には、そのシフトで実際に使用する勤務案内の確定版を保持する。

| 情報 | マスタ | シフト側 |
| ----- | ----- | ----- |
| 勤務先ID | あり | 参照 |
| 勤務先名 | 最新 | スナップショット |
| 住所 | 最新 | スナップショット |
| 交通案内 | 最新 | スナップショット |
| アクセス補足 | 最新 | スナップショット |
| 集合案内 | 最新 | スナップショット |
| 更新日時 | 最新 | スナップショットの確定日時 |
| 参照元バージョン | あり | 確定時のバージョン |

既存DBの実際の保存形式は未確定なので、上記は必要な論理データ項目とする。実装では既存スキーマと整合させる。

### **5.2 スナップショットの作成タイミング**

シフト作成時に、その時点の勤務先マスタからスナップショットを生成する。

以後、マスタを変更しても既存シフトのスナップショットは自動変更しない。

これにより、過去の勤務履歴を後から書き換えてしまうことを防ぐ。

### **5.3 マスタ変更の反映フロー**

1

勤務先マスタを編集

住所・集合案内などを変更

2

変更を保存

マスタの最新版と変更履歴を保存

3

影響するシフトを確認

未来シフト・配置済みスタッフを一覧表示

4

反映するシフトを選択

対象ごとに更新前後を比較

5

反映を確定

スナップショット更新・監査・必要な通知

### **5.4 反映対象の制限**

| シフト状態 | 反映可否 |
| ----- | ----- |
| 未来・応募なし | 反映可能 |
| 未来・応募あり | 影響確認後に反映可能 |
| 未来・配置済み | 影響確認＋スタッフへの変更通知 |
| 勤務開始済み | 原則として反映不可 |
| 完了済み | 反映不可 |
| 取消済み | 反映不可 |

勤務開始済み・完了済みの記録に訂正が必要な場合は、通常のマスタ反映ではなく、専用の訂正・監査フローを使用する。

### **5.5 Worker側の表示**

Workerが見る勤務先情報は、そのシフトのスナップショットを正とする。

マスタが更新されても、Workerに表示する集合場所が勝手に変わらない。

シフトのスナップショットが明示的に更新された場合のみ、Worker側の表示を更新する。

変更通知には、変更された項目と新しい案内を含める。ただし、通知の内容に不要な個人情報は含めない。

### **6.2 無効化後の挙動**

| 対象 | 無効化後 |
| ----- | ----- |
| 取引先 | 新規案件の選択候補から除外 |
| 勤務先 | 新規業務の選択候補から除外 |
| 既存案件 | 関連取引先を保持 |
| 既存業務 | 関連勤務先を保持 |
| 既存シフト | スナップショットを保持 |
| 過去勤怠 | 変更なし |
| 未来の配置 | 自動取消しない |
| Workerへの通知 | 無効化だけでは送らない |

既存の案件・業務が無効マスタを参照している場合、編集画面では現在の参照値を表示し、警告を付ける。別の有効マスタへの変更は可能とする。

新規作成や新しい参照先への変更では、無効マスタを選択できない。

無効化と再有効化はサーバー側で権限・状態・関連データを再検証する。

### **6.3 再有効化**

無効マスタは再有効化できる。

再有効化後は新規案件・業務の候補に再び表示する。

ただし、再有効化しても過去のシフトスナップショットは更新しない。

## **7\. 状態遷移**

有効

新規参照可能

無効

既存参照のみ

状態は有効・無効の2種類とする。

名称や住所の編集は状態遷移を伴わない。

物理削除は通常UIに用意しない。誤登録や重複登録の整理が必要な場合は、関連参照の調査を含む別の管理手順で扱う。

## **8\. 変更履歴と監査**

取引先・勤務先の変更はすべて監査対象とする。

### **履歴の記録項目**

| 項目 | 内容 |
| ----- | ----- |
| 対象種別 | 取引先・勤務先 |
| 対象ID | マスタID |
| 操作 | 作成・編集・無効化・再有効化 |
| 操作者 | 管理者ID |
| 操作日時 | サーバー時刻 |
| 変更前 | 変更前の値 |
| 変更後 | 変更後の値 |
| 理由 | 無効化などで必要に応じて入力 |
| 結果 | 成功・失敗の区別 |

変更履歴は右ドロワーで閲覧する。

勤務先スナップショットの更新履歴は、マスタの変更履歴とは別にシフト側にも保持する。

これにより、「マスタの集合案内を変更した日時」と「特定シフトへ反映した日時」を区別できる。

履歴は権限のある管理者のみ閲覧可能とする。

## **9\. 操作権限**

| 操作 | Manager | System Admin | Worker |
| ----- | ----- | ----- | ----- |
| マスタ一覧 | 許可範囲 | 許可範囲 | 不可 |
| マスタ作成 | 専用権限 | 専用権限 | 不可 |
| マスタ編集 | 専用権限 | 専用権限 | 不可 |
| 無効化 | 専用権限 | 専用権限 | 不可 |
| 再有効化 | 専用権限 | 専用権限 | 不可 |
| 関連データ閲覧 | 許可範囲 | 許可範囲 | 不可 |
| 変更履歴閲覧 | 許可範囲 | 許可範囲 | 不可 |
| シフトへの変更反映 | シフト編集権限も必要 | シフト編集権限も必要 | 不可 |

シフトへの勤務先情報の反映には、マスタ閲覧権限だけでなく対象シフトの編集権限も必要とする。

Managerが自支店以外の案件・業務・シフトにアクセスできない場合、そのデータは一覧・件数・反映候補に表示しない。

影響範囲の一部が権限外である場合、すべての関連データを確認できる権限者による承認・実行を要求する。見えている件数だけで安全と判断して無効化しない。

権限はフロントエンドの表示制御だけでなく、RPC・RLS側で強制する。

## **11\. エラー・空状態**

| 状況 | UI・処理 |
| ----- | ----- |
| マスタ0件 | 「まだ登録されていません」 |
| 検索結果0件 | 「条件に一致するデータがありません」 |
| 名称重複 | 重複候補を警告 |
| 保存失敗 | ドロワーを維持し入力内容を保持 |
| 同時更新 | 競合を検出し再取得 |
| 無効化失敗 | 状態を変更せずエラー表示 |
| 影響件数取得失敗 | 無効化を実行させない |
| スナップショット反映失敗 | 対象ごとの結果を明示 |
| 権限なし | 操作不可・アクセス拒否 |
| 参照先が無効 | 既存値を表示し警告 |
| 履歴取得失敗 | 履歴の取得失敗を表示 |

複数シフトへの反映では、部分成功を曖昧にしない。処理単位ごとに成功・失敗を記録し、再実行時の二重更新を防ぐ。

### **実装時の安全条件**

現在進行中のPR-02・PR-03などのDB・権限変更と、今回のマスタ管理変更は分離する。

既存のRPC・RLSで実現できない操作は、新しい更新経路を設計・検証するまで有効化しない。

クラウドDBへの適用やmainへのマージは、別途承認された手順で行う。

* 配置済みスタッフへの案内変更通知が行われる。  
* 変更履歴・操作者・日時が保持される。  
* 権限外のデータを閲覧・更新できない。  
* 保存失敗・競合・部分成功を適切に扱える。
