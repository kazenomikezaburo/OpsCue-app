# **OpsCue Admin 共通ナビゲーション UI/UX 最終仕様書**

**Version:** 1.0  
**作成日:** 2026年10月22日  
**対象:** OpsCue Admin（管理者向けWebアプリ）  
**ステータス:** UI/UX基本設計確定・実装未着手

---

## **1\. 目的・設計方針**

OpsCue Adminのヘッダー、サイドバー、通知、アカウントメニューを統一し、管理者が必要な業務画面へ素早くアクセスできる共通ナビゲーションを構築する。

### **基本方針**

* 既存の白・ライトグレー・青を基調としたデザインを維持する。  
* 業務管理画面としての視認性と操作性を優先する。  
* デスクトップとモバイルで一貫した操作体系を提供する。  
* 既存の画面名、業務ロジック、権限、データ構造を不用意に変更しない。  
* 未実装機能へのリンクやダミー操作を本番UIに設置しない。  
* キーボード操作、フォーカス表示、タッチ操作にも対応する。

### **2.2 寸法**

| 要素 | 仕様 |
| ----- | ----- |
| ヘッダー | 高さ68px、画面全幅に固定 |
| サイドバー展開時 | 幅248px |
| サイドバー縮小時 | 幅64px |
| メニュー項目 | 高さ44px |
| メニューアイコン | 20px |
| サイドバー左右余白 | 12px（展開時） |
| グループ間隔 | 16px |
| レスポンシブ切り替え | CSSビューポート幅1024px |

ヘッダーはサイドバーの展開・縮小によって移動しない。サイドバーはヘッダーの直下から画面下端まで配置する。

## **3\. ヘッダー**

### **3.1 配置**

左側：

1. OpsCueロゴ  
2. サイドバー開閉ボタン

右側：

1. 通知ベル  
2. アカウントメニュー

ロゴはサイドバー内に配置しない。サイドバーが縮小しても常に表示する。

デスクトップとモバイルの両方で「OpsCueロゴ → 開閉ボタン」の順序を維持する。

### **3.2 ロゴ**

* 既存のOpsCueブランド表記を使用する。  
* ロゴのクリック先はAdminホームとする。  
* 未確認のロゴ画像・ブランドアイコンを新規採用しない。

### **3.3 ヘルプボタン**

現段階では表示しない。

将来的にヘルプ画面や操作ガイドが整備された場合に追加を検討する。

## **4\. サイドバー**

### **4.1 展開・縮小**

採用方式：**クリック開閉＋ホバーPeek**

| 状態 | 動作 |
| ----- | ----- |
| 展開 | 幅248pxでメニュー名とアイコンを表示 |
| 縮小 | 幅64pxでアイコンのみ表示 |
| 開閉ボタンクリック | 展開・縮小状態を切り替える |
| Peek | 縮小状態でホバーすると一時的に248pxへ展開 |
| Peek終了 | ホバー領域から離れると元の64pxへ戻る |

Peekはオーバーレイ方式とし、メインコンテンツの幅を変更しない。

縮小時はメニュー名をツールチップでも確認できるようにする。

キーボードフォーカスによるメニュー名の確認手段も提供する。

### **4.2 メニュー構成**

業務目的別の5グループを採用する。

**グループ1：メイン**

* ホーム  
* 要対応

**グループ2：案件・勤務管理**

* 案件  
* シフト運用  
* 勤怠

**グループ3：人員・取引先**

* スタッフ  
* 取引先  
* スキル・資格

**グループ4：連絡・サポート**

* ヘルプリクエスト  
* お知らせ

**グループ5：システム**

* 設定

グループ見出しは小さめのグレー文字で表示する。見出し自体はクリック不可とし、グループの折りたたみ機能は設けない。

「ホーム」「要対応」を最上部に配置する。

「設定」は他のメニューと分離し、サイドバー最下部に固定する。

### **4.3 選択状態**

現在表示中のメニューは、以下のスタイルで強調する。

* 背景：淡い青 `#EAF2FF`  
* アイコン：青 `#2563EB`  
* 文字：青系の強調色  
* 角丸：既存のOpsCueのUIと統一

ホバー状態と選択状態は視覚的に区別する。

### **4.4 縮小時の表示**

* メニュー名・グループ見出しを非表示にする。  
* アイコンを64px幅の領域内で中央配置する。  
* グループ間には細い区切り線を表示する。  
* ツールチップとPeekでメニュー名を確認できる。  
* 選択中メニューには淡い青背景を表示する。

### **4.5 要対応バッジ**

| 状態 | 表示 |
| ----- | ----- |
| 展開時・未処理あり | 件数バッジ |
| 縮小時・未処理あり | 小さなドット |
| 未処理0件 | バッジ非表示 |

件数は既存の「要対応」業務定義に従う。

通知の未読件数とは別に管理する。通知を既読にしても、業務上の未処理状態は変更しない。

### **4.6 スクロール**

* サイドバー自体はヘッダー下に固定する。  
* メニュー領域のみ独立して縦スクロールする。  
* スクロールバーは必要な場合だけ表示する。  
* 設定メニューはスクロール領域から分離して最下部に固定する。  
* サイドバーのスクロール位置は本文のスクロールから独立させる。  
* 縮小時・Peek時も同じ構造を維持する。

## **5\. モバイル・タブレット対応**

### **5.1 ブレークポイント**

| 画面幅 | ナビゲーション |
| ----- | ----- |
| 1024px以上 | 通常の248px／64pxサイドバー |
| 1024px未満 | オーバーレイドロワー |

### **5.2 モバイルドロワー**

* 通常時は非表示。  
* ヘッダーの開閉ボタンから左側に表示する。  
* 本文を押し縮めず、画面上に重ねる。  
* 背景タップ、閉じるボタン、Escapeキーで閉じられる。  
* メニュー選択による画面遷移後は閉じる。  
* ドロワー表示中は背後の誤操作を防ぐ。  
* メニュー高さ44px、アイコン20pxを維持する。  
* 設定メニューはドロワー最下部に固定する。

ドロワー上部の重複したOpsCueロゴ表示は避け、必要に応じて「メニュー」と閉じる操作を配置する。

## **6\. 通知ベル**

### **6.1 表示方式**

**ドロップダウン＋通知一覧ページ**を採用する。

通知ベルを押すと、最新の通知を最大5件表示する。

各通知の基本表示内容：

* タイトル  
* 概要  
* 時刻

ドロップダウン下部に「すべての通知を見る」を配置し、専用の通知一覧ページへ遷移できるようにする。

### **6.2 通知と要対応の区別**

* 通知：情報更新・お知らせなどを確認する機能  
* 要対応：管理者が判断・処理する必要のある業務

通知の既読状態と業務の処理状態は独立して扱う。

通知の種類、既読操作、未読件数、遷移先については、既存実装と権限設計を確認してから詳細を確定する。

## **7\. アカウントメニュー**

### **7.1 ヘッダー表示**

デスクトップでは以下を表示する。

* アカウントアイコン  
* ユーザー名  
* 権限名

狭い画面では表示幅に応じてアイコン中心の表示にする。

### **7.2 ドロップダウン**

初期構成は最小限とする。

1. 現在ログイン中のユーザー情報  
2. ログアウト

アカウント情報ページ、個人設定ページなどは、現段階では追加しない。

ログアウトは既存の認証フローを使用する。

## **8\. カラー・境界線**

採用テーマ：**バランス型**

| 用途 | カラー |
| ----- | ----- |
| ヘッダー背景 | `#FFFFFF` |
| サイドバー背景 | `#F8FAFC` |
| メインコンテンツ背景 | `#F9FAFB` |
| 選択中メニュー背景 | `#EAF2FF` |
| アクセント | `#2563EB` |
| 境界線 | `#E5E7EB` |
| 通常文字 | 既存のOpsCue文字色を優先 |

境界線は基本1pxとし、ヘッダー下とサイドバー右側に配置する。

不要な強い影や装飾は使用しない。

## **9\. 余白・密度**

| 項目 | 仕様 |
| ----- | ----- |
| メニュー高さ | 44px |
| アイコンサイズ | 20px |
| サイドバー左右余白 | 12px |
| グループ間隔 | 16px |
| グループ見出し | 小さなグレー文字 |
| 縮小時グループ境界 | 細い区切り線 |

64px縮小時は、展開時の左右12pxという数値を機械的に適用せず、アイコンを中央配置することを優先する。

## **10\. 操作フィードバック・アニメーション**

以下は最終実装に向けた推奨値であり、詳細な動作検証後に調整できる。

| 操作 | 推奨仕様 |
| ----- | ----- |
| メニューホバー | 薄いグレー背景 |
| 選択中 | 淡い青背景＋青アイコン |
| キーボードフォーカス | 視認できる青いアウトライン |
| サイドバー開閉 | 約200ms |
| Peek開始 | 約200msのホバー待機 |
| Peek終了 | 誤閉じを防ぐ短い猶予 |
| モバイルドロワー | 左からスライド |
| ドロワー表示中 | 背景を薄暗くする |

アニメーション軽減設定が有効な環境では、動きを抑える。

## **11\. アクセシビリティ**

* アイコンのみのボタンに適切な名前を設定する。  
* キーボード操作でメニュー・通知・アカウントにアクセスできる。  
* ドロップダウンとドロワーはEscapeキーで閉じられる。  
* フォーカス位置を視認できる。  
* ツールチップだけに重要情報を依存させない。  
* ホバー操作が使えないタッチ端末でも全機能を利用できる。  
* ドロワー表示時はフォーカス管理と背後の操作制御を行う。  
* 色だけに依存せず、選択状態や未処理状態を判別できるようにする。

## **12\. 実装前の確認事項**

以下は既存実装を確認するまで未確定とする。

1. OpsCueロゴの正式アセットとホームへのリンク仕様  
2. 通知の取得元、未読状態、既読操作、関連画面への遷移  
3. 「要対応」の件数算出方法  
4. アカウント名・権限名の取得元  
5. ログアウト処理とセッション管理  
6. サイドバーの開閉状態を保存する方法  
7. Peekのホバー判定とツールチップの競合防止  
8. 既存のルーティング、画面名、メニュー表示権限  
9. モバイルドロワーの適切な実寸幅  
10. アニメーション時間・ホバー待機時間の最終調整

## **13\. 実装範囲・変更禁止事項**

### **対象**

* Admin共通ヘッダー  
* Admin共通サイドバー  
* レスポンシブナビゲーション  
* 通知ベルの表示UI  
* アカウントドロップダウン  
* 共通スタイル・操作状態

### **対象外**

* Worker UI  
* 業務データの構造変更  
* DBスキーマ変更  
* RLS・認証権限の緩和  
* 案件・シフト・勤怠などの業務ロジック変更  
* ホーム画面のKPI定義変更  
* 未承認の新機能追加

既存機能の動作を維持し、必要な場合は別途変更承認を得る。

## **14\. 完了条件**

* ヘッダーとサイドバーが指定寸法で表示される。  
* サイドバーの展開・縮小・Peekが正常動作する。  
* 現在のページが正しく強調表示される。  
* 5グループのメニューが適切に配置される。  
* メニュー領域のスクロールと設定固定が両立する。  
* 1024px未満でドロワーに切り替わる。  
* 通知ドロップダウンと一覧ページへの導線が動作する。  
* アカウント情報とログアウトが正常動作する。  
* キーボード操作とモバイルタッチ操作で利用できる。  
* 既存のAdmin業務機能に回帰不具合が発生しない。
